# 修改文档：当前文件内容是唯一事实

你记忆中"这个文档应该是什么样"不是事实。用户随时可能在外部编辑器里手动修改文档：修正错误、调整措辞、增删内容。如果修改时按记忆重写，用户的手动修改会被静默覆盖，而且往往难以察觉。

## 核心规则

1. **先读后改，每次都读。** 动手修改任何已有文档前，必须重新读取该文件在磁盘上的当前内容。即使是本会话刚生成的文档也一样——用户可能刚在编辑器里保存过。

2. **磁盘内容优先于记忆。** 如果当前文件与你记忆中的版本不一致，一律以文件为准。差异处就是用户的手动修改，必须原样保留：
   - 不要"纠正"回你原来写的版本
   - 不要在回复中评判或质疑用户的修改
   - 只有当用户的修改与本次任务要求直接冲突时，才向用户指出并询问，不擅自取舍

3. **最小化编辑。** 只修改本次请求涉及的内容，用精确的局部替换完成，不整段重写、不整文件重写。无关段落即使你觉得有问题，也保持原样。

4. **确需大范围重排时**，先将当前文件完整读一遍，逐段核对：新版本中每个非目标段落与磁盘当前内容逐字一致，之后才落笔。

5. **改完自查。** 对比修改前后：除目标改动外没有其他内容变化；你读到的用户手动修改全部还在。

## 示例

背景：AI 此前生成了文档，用户随后手动把"超时时间 30s"改为"超时时间 60s"，并修正了一个参数名。现在用户要求："在概述里补充一句支持断点续传。"

好的做法：读取当前文件 → 只在概述节加一句 → 其余内容（含 60s 和修正后的参数名）逐字保留。

不好的做法（禁止）：按记忆重写全文，把 30s 和旧参数名写了回去。

## 汇报

向用户汇报改动时，可以简短说明"保留了文档中的手动修改"；发现文档与记忆版本不一致时，提示用户"检测到手动修改，已保留"即可，不做过多评论。

## 适用范围

本规则同样适用于代码文件及其他任何文件的修改，不仅仅是文档。
